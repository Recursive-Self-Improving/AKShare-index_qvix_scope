# Repository guidance

## Lessons

- Use `uv sync --frozen` with Python 3.14 and this lock. AKShare 1.20.53 is the last approved version with `index_news_sentiment_scope`; 1.20.54 removed it. The installed JavaScript decoder imports `py_mini_racer`, but its distribution metadata name is `mini-racer` (not `py-mini-racer`).
- Capture `requests` response-hook `.content` before application decoding, including redirect responses; these are HTTP-decompressed bytes, not wire bytes. Request read/connect timeouts alone are not wall-clock bounds: acquisition uses one 45-second subprocess per source.
- Historical AKShare documentation puts the sentiment anchor immediately before its own `###` title. Splitting at the first heading yields an empty excerpt; bound the exact example using its explicit final dataframe row-count/fence, then transcribe only printed dated rows.
- Sina first observation is not official index inception. Store authoritative base/release dates and per-row pre-release/pre-base flags. In particular, vendor 沪深300 history starts before both official base and release; its reconstruction method remains unknown. 科创综指 includes dividends and is not the 科创50 price index.
- Keep provider failures nonzero and documentation examples separate. A successful offline report/hash check cannot establish genuine sentiment availability or browser interaction correctness. Never edit the orchestrator's goal ledger from an implementation slice.
- AKShare 1.20.53's sentiment wrapper raises a pandas column-projection KeyError for a valid HTTP200 `[]`. Keep the actual invocation/capture; recognize only that empty projection and strictly decode the captured body before treating it as observed empty success. Coverage of merged sentiment must be derived from all successful revisions, separately from the latest response; never rewrite an immutable acquisition manifest to migrate derived accounting.
- RQData documents `rqdatac.news.get_stock_news` with per-article and per-company sentiment from 2017; this is a separately entitled alternative, not proof of the same ChinaScope market index. CnOpenData/通联 documents company-level daily news sentiment indices, not the original market series. Vendor history and redistribution remain subject to actual access and license.
- Root `ruff check .` includes archived `.py` evidence scripts; run final union lint after reviewers add scripts.
- AKShare 1.20.53 `index_option_50etf_qvix` reads the first five columns of a GBK CSV via `http.get_buffer`; its 2026-11-15 response contained unordered dates and two conflicting 2026-11-02 values. Successful wrapper execution is not validated history; never silently deduplicate or infer dates.
- The provider's HTTPS `k.csv` matched the 2026-11-15 pinned-wrapper HTTP body byte-for-byte, and its historical chart script uses the same file. This does not authenticate the earlier HTTP transfer or independently resolve source conflicts; TLS, source quality, and redistribution permission are separate questions.
- QVIX quality normalization compares complete decoded OHLC tuples, not close alone: equal-close/different-open candidates still conflict and all four selected fields must be null. Keep source-order wrapper output and every one-based raw ordinal separately from sorted unique-date observations; normalization notices must not conceal quality defects outside the selected window.
- Bind a common comparison trace to its snapshot's verified comparator identity/hash, including original comparator staleness. A later index refresh must not silently change the calendar of a stale QVIX snapshot.
- QVIX full-calendar accounting must replay the comparator's full retained Sina raw history, not its request-filtered CSV. Selected holes are the full in-observed-bounds hole set filtered to the request, even when no source row survives. Keep immutable acquisition references/times mandatory; a derived format migration is not a fetch.
- `report.html` visible wording is a verified contract: `app/verify.py` (`visible_index`/`visible_qvix`) independently rebuilds per-panel/per-feed disclosure text; `test_visible_per_feed_and_index_disclosure_tampering` rejects removal, contradictions and hidden paragraphs. Update both when changing wording.
- The seven pinned QVIX wrappers share `__get_optbbs_daily`; its `lru_cache` does not cache exceptions. Track the actual loader boundary, stop after shared failure, and commit each validated sibling durably before starting the next. A wrapper exception before loading is local, not proof of a shared failure.
- Sparse QVIX source bounds use nonblank candidates, close bounds use unambiguous finite closes, and common bounds include blank rows. Preserve error-only and blank tails as nulls without extending close coverage; a fresh no-close snapshot replaces old prices and is not stale.
- 深证100 399330 has official base 2002-12-31 and release 2006-01-24; the retained compiler factsheet separately identifies 399004 as 深证100R. Family anniversary wording is not a release date for 399330.
- Immutable native completion hashes only establish identity, not completeness: require usable UTC attempt/success/finish/acquisition timestamps before recovery or promotion, and test mutations of the immutable result itself. Visible HTML disclosure checks must bind ancestor context, not merely paragraph attributes or JSON; reject hidden/style-bearing and non-contract containers.
- Security review: `requests.get` follows redirects unless `allow_redirects=False`; rejecting multiple captures afterward does not prevent redirected requests to internal services. Artifact hashes and offline accounting establish consistency, not source authenticity or HTML script safety. The chart builder does not run full manifest validation before rendering, so manifest-derived HTML still needs escaping.
- The pinned development dependency pytest 9.0.2 is affected by local UNIX temporary-directory vulnerability CVE-2025-71176 / GHSA-6w46-j5rx-g56g, fixed in 9.0.3 (https://osv.dev/vulnerability/GHSA-6w46-j5rx-g56g). Matching installed files to published PyPI wheels does not rule out compromised upstream releases or unreported vulnerabilities.
- 2026-11-16 report redesign: visible disclosures list only deviations (non-zero counts, stale/failed/unknown states), not zero counts, hashes or fresh timestamps; container path is now `section.panel > div.status > p`, and QVIX `quality ok/warn` class is verified against state. The header `#summary` stats and bottom `#quality-table` (snapshot IDs, comparator staleness) are verified cell-by-cell (tag, attrs, text) by `visible_summary`/`visible_quality_table`; change both sides together. Chrome headless `--window-size` below ~500px does not reproduce phone-width Plotly sizing; don't treat that screenshot as mobile proof.
- Daily publication has a stricter boundary than acquisition: exit1 may be eligible fresh QVIX partial or ineligible fatal/stale. Verify actual invocation identity/window/times and all member states before deciding. Use QVIX common raw dates (including blank dates), not nonblank/close dates, for cross-run source-loss protection; never resurrect prices into new nulls. Keep standard-library publication separate from acquisition dependencies, and deploy Pages explicitly because GITHUB_TOKEN commits do not trigger branch Pages builds.
- Cached QVIX acquisition precedes later members' attempts: bound shared time to the measured invocation/enclosing manifest and successful completion, retaining immutable shared identity and each member's attempt/success/finish order. Advancing-clock real preparation fixtures expose errors hidden by constant clocks.
- Ordinary non-force push is not exact-base CAS: a concurrent rollback can still fast-forward. Require the full publication parent list exactly `[receipt base]` plus one explicit `--force-with-lease=refs/heads/<branch>:<base>` push of that commit; no generic force/fallback/retry/rebase. This preserves history but cannot detect ABA. Pages failed-job reruns increment attempt and reject old receipts; all-job reruns after persistence have obsolete event bases. Exact-byte deployment recovery is authorized external/manual work, not a new refresh dispatch or a supplied deploy-only command.
- Same-day refresh freezes the inclusive UTC current date, not yesterday; latest source dates are observations, not an official trading calendar or proof that today's data is complete. Observed 2026-11-16 `Last-Modified` times were 09:37 UTC for QVIX and 10:24 UTC for Sina 深证100; these are not first-publication times. Hourly runs at :15 avoid top-of-hour congestion but do not guarantee dispatch or source readiness. GitHub `active` plus zero runs does not identify why a schedule was missed.
