### Material source defect: blanks versus spreadsheet error tokens

Existing v3 requires every OHLC field in every shared raw row to be finite and would reject six sparse columns and several requested feeds, or silently lose closes if pandas `errors='coerce'` is treated as source truth. [sparse-summary.json](matched-qvix-evidence/sparse-summary.json) independently counts **raw** tokens. Blank rows outside a feed's observed history are not invented zero observations. Spreadsheet errors are not blanks: 50index has `#VALUE!` 33, `#DIV/0!` 24, `#NUM!` 2, `#NAME?` 728 tokens; 300index has 63, 26, 0, 722 respectively plus eight `#N/A`; 100etf has eight `#NUM!`; 300etf has four `#VALUE!`, four `#NUM!`, and one malformed `22。27`; kcb has six `#NUM!`. These are token counts across OHLC, not distinct rows. 50etf and cyb have none. Nonempty raw bounds for 50index and 300index extend to 2026-11-13 but much of the tail is error tokens, not valid values. Raw finite-close row counts including error-containing OHLC are 753, 2849, 942, 1482, 1661, 997, 827 in table order; includes duplicates and zeros, not clean-date counts. The index feeds contain raw zero closes (33 and 42 rows), and kcb one; no evidence makes zero automatically a missing sentinel. Thus the last complete-case date is not a claim of latest available close, nor is a source error an observed finite close.

## Proposed reviewed contract: clean v4 cutover

1. **Registry and binding.** Introduce one ordered index registry including `sz399330`, and seven distinct QVIX feed definitions with exact callable, positional date/OHLC schema, label, provider URL, and a deterministic comparator. Proposed fixed comparators: 50index and 50etf → sh000001 (preserves v3 continuity); 100etf → sz399330; 300index and 300etf → sh000300; cyb → sz399006; kcb → sh000688. Every feed has one calendar, shared across its mapped panels, not silently recalculated against each panel. Calendar identity includes feed code, verified immutable original acquisition reference/hash, raw hash, original acquisition time, and stale-at-binding flag. Replay full raw comparator independent of request-window CSV. Missing or stale comparator means unknown/stale coverage and at least partial, never clean. A failed later refresh retains each old QVIX snapshot's own comparator and its original staleness; a new index refresh cannot change it.
2. **One bounded common acquisition.** Eight index workers and one QVIX group worker, each with the existing subprocess wall bound and response capture. Invoke the seven pinned wrappers against one captured response/cache when the shared load succeeds; shared-load failure stops further loader calls, as specified below. Record actual invocation names, result/error and hashes separately; validate common transport once and store raw body once. Per-wrapper failure is feed-local; global raw-structure failure invalidates every member. Preserve one immutable transport/body identity with explicit per-feed origin/member binding. No endpoint change, network replay, retries, or substitutions. A later implementation must perform its own real acquisition; this scratch spike is not that run.
3. **Reviewed extension for sparse/errors.** Validate raw date, width, selected positional schema and every row across the entire response before selection; compare wrapper output row-by-row, including pandas-coerced missing values, with independent raw interpretation. Require strict canonical valid dates; structural/schema/date/nonfinite numeric/unknown encoding errors are fatal. Represent all-empty selected OHLC as *no feed observation*; retain ordinal and count so pre-coverage blanks and internal holes are distinguishable. Treat explicitly observed `#VALUE!`, `#DIV/0!`, `#NUM!`, `#NAME?`, `#N/A`, and malformed nonempty numeric tokens such as `22。27` as **source-invalid cells**, not blank, not corrected or interpreted numbers: retain exact raw spelling, field and ordinal, mark that observation partial and preserve independently valid finite close if unambiguous. No inferred decimal repair. Any other malformed token follows the same explicit source-invalid-cell treatment rather than arbitrary coercion; structural errors still fatal. This is a substantive departure from v3's all-fields-finite fatal policy, necessary to deliver observed closes, and must be independently reviewed before adoption. Zeros are finite source values, not silently filtered; visibly flag zero and invalid cells, do not assert economic validity. Preserve source-order wrapper bytes and raw data as the ground truth.
4. **Grouping and partial quality.** For each date group compare the full four-field tuple including missing/invalid field identity and exact bad token; retain all source ordinals and candidates. Multiple distinct tuples make **all OHLC null**, even when close agrees; no revision merge or winner. An unambiguous incomplete candidate may retain each independently finite field including close, with missing/invalid cells null and explicit quality; no envelope assertion unless all four fields are finite. Fully blank records are absence, not a candidate; retain their ordinals separately, including blanks colliding with a populated date. Exact duplicates are notices; envelope anomalies keep finite values and flags. Bounds, counts, overlap, trace and no-close state are specified below; none imply official-calendar completeness.
5. **State and migration.** Each feed state is attempt + optional whole immutable evidence snapshot, which need not contain any usable close. Fresh partial replaces an earlier snapshot even if no close is available; only fatal acquisition/validation failures reuse a prior same-feed snapshot, marked stale. No per-date stitching; correction replaces the whole snapshot. Any required feed partial/failure makes overall fetch nonzero; still publish validated partials atomically, keep previous active pointer if validation/promotion fails. Create a new versioned v4 manifest; an explicit one-time derived view may reference verified v3 origins and times, especially old 50etf, but must not claim a fetch or mutate historical manifests, and must not reinterpret v3 sidecars as v4 without verified rederivation. Keep a hashed `previous` reference, compact state, per-feed quality sidecars once, and reject incompatible active schema; no runtime compatibility shims. Preserve all historical artifacts unchanged.
6. **Plot and disclosure.** `app/chart.py` must retain the existing 9cb3397 page layout/styles/navigation and use its established Plotly controls, extending each panel's trace list rather than replacing the layout. Ordered panels per table; one index close left, one/two named QVIX closes right (%), distinct colors/dashes and individually togglable legend traces, readable without overlapping controls. Every feed trace uses its own bound calendar, source/window bounds and nulls, `connectgaps=false`; same feed on two panels has identical trace data. Explicit visible per-feed attempt, source snapshot/time, stale status, observed range, conflicts, source-invalid fields, zero notices, holes/extras, and comparator provenance; do not obscure one feed's warning with another's success. Preserve offline JS, zoom/reset, slider/range buttons and proxies/timing/transport/license limitations.

### Deterministic fresh, selected and fatal states (F1)

All fresh rows below apply identically with and without a prior success: a fresh validated snapshot replaces the prior active feed snapshot, and is retained with raw, wrapper and quality evidence; `stale=false`. “Unavailable” means close trace, not snapshot. Attempt status is `partial` except a full clean history with an empty selection remains `success` if all full-feed obligations pass. Overall exit is nonzero if any required feed is partial or fatal; otherwise zero. Promotion failure is separate, nonzero and leaves the previous active pointer unchanged.

| Validated full response / selected window | Attempt and close availability | Full and selected display |
|---|---|---|
| All selected OHLC fields blank in the full feed | fresh partial; no close anywhere | full source and usable-close bounds absent; common bounds and blank counts retained; selected trace null/empty and selected close bounds absent |
| Nonblank full feed, no raw finite close (including all-error) | fresh partial; no close anywhere | nonempty source bounds retained; usable-close bounds absent; errors and null trace visible |
| Raw finite closes exist but every date conflicts, or otherwise no unambiguous finite close survives | fresh partial; no close anywhere | source bounds retained; usable-close bounds absent; conflicts and candidate evidence retained, all conflicting OHLC null |
| Full history has usable closes, selected window has none or no source rows | fresh status determined by full quality, not the selection; selected close unavailable | retain full source and close bounds; selected source/close bounds independently absent as appropriate; show selected null/empty trace and selected bounded holes |
| Ordinary partial with at least one unambiguous finite close | fresh partial | show independently computed full and selected bounds, finite values and nulls |
| Fatal transport, global validation or feed-local wrapper/validation failure | fatal, nonzero; prior same-feed whole snapshot only, `stale=true`, if present; otherwise no snapshot and unavailable | show failed attempt separately from original snapshot identity/time and its full/selected ranges; never borrow a sibling or splice prices |

An all-blank required feed is always partial, even with no internal blank dates. Error/blank/conflict/no-close are evidence quality, not fatal structural errors. Stale means reuse after fatal only, never merely a missing selection. A fresh snapshot with no closes is still a snapshot; a previous success is not a fallback for it.

### Date sets, counts and trace construction (F2)

Definitions are per feed over the **entire** structurally valid response before applying the inclusive requested window `W`. `D` is the set of dates in the common raw response; row counts count raw ordinals, date counts count distinct dates. `N` is dates with at least one nonblank selected OHLC field in any row. `B` is dates with at least one all-blank OHLC row; `B0 = B \\ N` is dates with no nonblank candidate. Blank rows colliding with nonblank rows remain recorded but do not null their candidate. Common bounds are `[min(D), max(D)]`; nonempty source bounds `S=[min(N),max(N)]`; usable-close bounds `U=[min(V),max(V)]`, where `V` is dates whose grouped, unambiguous normalized close is finite, including zero. Any empty set has absent bounds, never inferred endpoints. Error-only dates belong to `N`, not `V`; conflicts are not in `V` even if their raw candidates contain finite closes.

Partition all-blank **rows** by their date relative to `S`: prefix `< min(N)`, internal within `S`, tail `> max(N)`; if `N` is empty, use a separate `all-blank/no-source-bounds` bucket for every blank row/date, not an arbitrary prefix or tail. For **dates**, apply these same regions to `B0` (disjoint); additionally disclose `B ∩ N` as blank-collision dates and count colliding blank rows separately. Prefix alone does not degrade a feed; internal and tail `B0`, invalid cells, conflicts, envelope anomalies, comparator gaps/extras, or no usable full close cause partial. Zero is a visible notice, not independently a partial-quality defect. Tail blanks are counted through common response end, and do not extend `S`, `U`, or imply a close at the request end.

Let `C` be the verified bound comparator's full raw date set, including original stale-at-binding identity; `C` is unknown, not empty, when absent. Define `Cs = C ∩ S` when `S` exists, otherwise empty if C is known. On known C: `absent = Cs \\ D`; `blank = Cs ∩ B0`; `conflict = Cs ∩ K`, where `K` is the set of dates with distinct nonblank tuples; `invalid_close = Cs ∩ I`, where `I` is nonconflicting `N` dates whose sole distinct candidate has invalid close; `missing_close = Cs ∩ M`, where `M` is nonconflicting `N` dates whose sole distinct candidate has blank close. These five sets are disjoint, and their union is `holes = Cs \\ V`. A date with invalid non-close fields and a finite unambiguous close belongs to `V`, not to holes. `source_only = N \\ C`, including invalid and conflict dates; additionally `blank_source_only = B0 \\ C` (separate, not a price observation). A stale C supplies only explicitly stale relative comparisons, never a clean/current completeness claim; when C is absent all comparator-derived sets/counts are unknown, not zero. None of these sets assumes official sessions.

Full counts are cardinalities of these full sets, with candidate/duplicate, invalid-token/field, zero, envelope and raw-blank **row** counts separately labelled; affected-date counts deduplicate by date. Invalid-field affected dates, zero raw rows, conflicts, duplicate notices, blank-collision rows, and source-only labels may overlap; never sum them as mutually exclusive. For each date set `X`, selected count is `|X ∩ W|`; for each row category, selected rows are those whose raw date is in `W`. Selected holes are exactly `holes ∩ W`, including a window with no source rows; do not recompute bounds from selected rows. Selected source and close bounds are min/max of `N ∩ W` and `V ∩ W`, independently; full bounds remain unchanged. Outside `S`, disclose observed blank tail and error/no-close dates separately, not extrapolated comparator holes. `sparse-summary.json`'s `complete` means all cells populated including invalid tokens, not finite-complete; active accounting names it `all_cells_nonblank` and counts finite-complete separately.

Trace dates are the sorted union of `N`, internal/tail `B0` (all `B0` if `N` empty), and `holes`, filtered to `W`; `holes` contributes only when C is known. Emit the grouped close for `V`, otherwise explicit null, with `connectgaps=false`. This includes source-only internal blanks/errors and trailing blanks even without a comparator; no prefix is needed for an ordinary source-bound trace. Keep invalid/conflict/error-tail dates as null even outside usable-close bounds; preserve zero as finite. No synthetic daily grid, post-response extrapolation or official-calendar assertion.

### Shared-worker durable protocol (F3)

Use a unique group attempt identity; durably capture immutable transport metadata/body hash and acquisition time, then globally validate encoding, common CSV shape/consistent row width and canonical dates over all rows before accepting any member. Global transport, encoding, CSV width or date failure invalidates all feeds; no completed feed may be promoted against an invalid common body. Required feed-local positional schema, numeric nonfinite/conversion, wrapper exception or wrapper/raw mismatch fails only that feed after common validation; malformed nonnumeric tokens remain source-invalid under §3. Do not infer a global CSV-width failure from a single feed's positional selection failure.

`lru_cache` does not cache exceptions: after any shared loader/transport failure, stop invoking wrappers immediately, never call the loader again in this group, record the actual invoked wrapper and failure, and mark all remaining wrappers **not invoked**, failed due to the shared cause. Do not claim seven executions. Once the shared load succeeds, a feed-local failure does not stop later siblings or reload the body. Record per-feed invoked/not-invoked, completion/error and timestamps honestly.

Before starting each next wrapper, durably flush that member's source-order wrapper bytes, independently validated raw/normalized/quality artifacts and a completion record, with hashes and a binding to group attempt, feed identity, expected column mapping, shared body/transport identity, and original acquisition time; publish completion atomically only after its referenced artifacts are durable. On group timeout, crash or nonzero worker exit, the parent recovers and independently verifies the shared global validation and each complete member's binding/hash and full validation; preserve those members as fresh results. Fail unfinished members with actual invoked/not-invoked/termination metadata and use only each member's own prior snapshot, stale if available. A partial/incomplete completion record is not a success. Invalid shared identity/global validation invalidates all members; invalid member binding fails that member, never a sibling by association. Reject substituted member/body, time, feed or mapping. Keep immutable attempted evidence on failure, and perform one independently validated atomic active-pointer promotion; promotion failure leaves the previous pointer intact.
