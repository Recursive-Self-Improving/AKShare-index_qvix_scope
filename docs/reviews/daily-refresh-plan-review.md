## GitHub semantics checked independently

Read current primary documentation during this review:

- [Schedule/manual events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule): UTC default; default-branch schedule; delayed/dropped runs and public-repository inactivity disabling. Manual dispatch can target other refs, so the explicit default-branch restriction matters.
- [Concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency): default pending replacement remains possible with `cancel-in-progress: false`; this is not durable exactly-once delivery.
- [Artifact validation](https://docs.github.com/en/actions/tutorials/store-and-share-data#validating-artifacts): digest mismatch produces a warning. Fatal explicit receipt/payload hash verification is necessary at the writer boundary.
- [Pages publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#troubleshooting-publishing-from-a-branch): `GITHUB_TOKEN` pushes do not trigger branch builds.
- [Custom Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages): explicit artifact dependency, `pages: write`, `id-token: write` and deployment environment support the chosen boundary.
